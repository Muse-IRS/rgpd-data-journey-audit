# Privacy Readability Reference

This project uses a public readability principle: a user should be able to understand, before or during use, what kinds of data are involved, why they are used, where they may go, and what controls or rights are available.

## Reference logic

The project may refer to public privacy readability approaches, including Apple-like privacy presentation patterns, as an inspiration for clarity:

- categories of data;
- purposes of use;
- user controls;
- transparency before action;
- clear distinction between local processing and data transmission.

## Boundary

This project is not affiliated with Apple.

It does not copy Apple interfaces, wording, trademarks or proprietary presentation systems.

The reference is conceptual only: make privacy understandable before the user is forced to trust a hidden process.

## Applied rule

For each module or audited service, the interface should answer:

```text
What data?
From where?
For what result?
Stored where?
Sent where?
Used by whom?
For what purpose?
For how long?
Which rights?
Which action?
```
